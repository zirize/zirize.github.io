Building QEMU for retro guests: integer scaling, a non-blocking LPT and CUE/BIN audio CDs

Three independent QEMU patch series for running DOS, Windows 9x and Windows XP guests on a modern Linux desktop, and how to build them into one binary.

Build steps qemu-wayland-scaler qemu-parallel-port-freeze qemu-cue-bin

Running old games and applications under QEMU on a Wayland desktop tends to hit the same three walls:

  • The 640×480 guest is blurry when enlarged, the mouse drifts or crawls on a HiDPI screen, and the Windows XP mouse feels slow.
  • Printing to LPT1 freezes the whole VM — display, monitor and SIGTERM — when the print server behind a socket stops reading.
  • Game CDs ripped as .cue/.bin play no CD music, and Windows CD Player sees no audio disc.

Each has its own patch series and write-up. This page shows how to combine them.

1. The three series

The series touch disjoint parts of QEMU. Without their options — no scaler=, a file chardev, an .iso image — QEMU behaves as upstream.

2. Applying all three and building

mkdir qemu-retro && cd qemu-retro
git clone https://gitlab.com/qemu-project/qemu.git
git clone https://github.com/zirize/qemu-wayland-scaler.git
git clone https://github.com/zirize/qemu-parallel-port-freeze.git
git clone https://github.com/zirize/qemu-cue-bin.git

cd qemu
git checkout -b retro 5f664cd37a      # QEMU 11.1.50, the base all ten patches were checked on

git am ../qemu-wayland-scaler/patches/qemu-master/000[1-6]-*.patch
git am ../qemu-parallel-port-freeze/patches/0001-parallel-nonblocking-tx.patch
git am ../qemu-cue-bin/patches/000[1-3]-*.patch

./configure --target-list=i386-softmmu,x86_64-softmmu --enable-sdl --enable-pipewire
ninja -C build

SDL is needed for scaler=; the audio backend (PipeWire here, or PulseAudio/ALSA) carries CD audio. The qemu-wayland-scaler repository also has the scaler series rebased onto the screamer fork for Mac OS 9 guests.

3. One command line using all three

./build/qemu-system-i386 \
  -enable-kvm -M pc -m 512 \
  -display sdl,scaler=integerplus \
  -audiodev pipewire,id=pw0 \
  -device AC97,audiodev=pw0 \
  -chardev socket,id=lpt0,host=127.0.0.1,port=9100,server=off \
  -parallel chardev:lpt0 \
  -drive file=disk.qcow2,if=ide,index=0,media=disk \
  -drive file=/path/to/game.cue,if=ide,index=2,media=cdrom

Display and mouse

  • Use -display sdl rather than gtk on Wayland; SDL handles pointer constraints and relative motion natively.
  • scaler=integer keeps an exact integer multiple with borders; scaler=integerplus scales up by an integer, then stretches to fill the window.
  • Do not add gl=on: the GL path ignores scaler= and always filters bilinearly.

Parallel port

  • When the socket peer stops reading, the guest sees a busy printer and waits; QEMU, its display and its monitor stay responsive.
  • A file chardev never fills up and was never affected.

CD-ROM

  • Point the CD-ROM at the .cue; the .bin files are found next to it.
  • With exactly one -audiodev the CD-ROM uses it automatically; with several, add -global ide-cd.audiodev=pw0.
  • To swap discs in Windows 98 SE from the monitor, send eject, wait about 1.5 seconds, then change, so CD Player notices the new disc.

Why, and what was actually tested: qemu-cue-bin.

Windows XP refuses “Enable digital CD audio”

An XP VM that first booted on an unpatched QEMU has cached “no CD-DA” for the drive under HKLM\SYSTEM\CurrentControlSet\Control\Class\{4D36E965-E325-11CE-BFC1-08002BE10318}\0000\DigitalAudio (CDDASupported = 0, CDDAAccurate = 0) and never re-checks. In Device Manager, uninstall QEMU DVD-ROM and scan for hardware changes (or reboot), then tick the checkbox again. Deleting the DigitalAudio key and rebooting works too.

Verified

On 2026-11-21 all ten patches were applied in the order above onto QEMU 5f664cd37a with no conflicts, and qemu-system-i386 was built with SDL and PipeWire. The combined binary accepts the scaler= option and passes the qemu-cue-bin Linux test on pc and q35. Guest-level testing of each feature is described on its own page.
